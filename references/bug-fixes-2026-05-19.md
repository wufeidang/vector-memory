## Bug 1: `clear_memories` 中 `_client` 为 None

### 现象
```
❌ 环境清理: 'NoneType' object has no attribute '_client'
```

### 原因
`clear_memories` 清空集合后执行 `_client = None`，但后续代码仍尝试访问 `_client._client`。

### 修复
```python
# 修改前
collection = _get_client()
client = collection._client

# 修改后
collection = _get_client()
client = collection._client if hasattr(collection, '_client') else _get_chroma_client()
```

### 影响函数
- `clear_memories`

## Bug 2: `get_stats` 中 `collection.get()` 返回 None

### 现象
```python
all_data = collection.get(include=['metadatas', 'documents'])
# all_data 可能为 None
total_count = len(all_data.get('ids', []))  # TypeError
```

### 原因
ChromaDB 的 `collection.get()` 在某些边界情况下返回 None。

### 修复
```python
try:
    all_data = collection.get(include=['metadatas', 'documents'])
    if all_data is None:
        all_data = {'ids': [], 'metadatas': [], 'documents': []}
    total_count = len(all_data.get('ids', []))
except Exception:
    total_count = 0
    all_data = {'ids': [], 'metadatas': [], 'documents': []}
```

### 影响函数
- `get_stats`

## Bug 5: 版本管理 text_hash 匹配失败

### 现象
```
❌ 版本管理 - 更新: ID 相同=False, version=1, prev=None
```

### 原因
版本匹配基于 `text_hash`，但修改文本内容后 text_hash 不同，无法匹配到同一记忆。

### 修复
改为基于 `category + device` metadata 匹配：

```python
match_idx = None
# 版本匹配：优先匹配 metadata 标识（category + device），其次匹配 text_hash
for i, meta in enumerate(existing_metadatas):
    if force_new:
        continue
    # 检查是否是同一记忆（通过 category + device 标识）
    meta_category = meta.get('category')
    meta_device = meta.get('device')
    input_category = metadata.get('category')
    input_device = metadata.get('device')
    
    # 如果 category 和 device 都匹配，认为是同一记忆
    if (input_category and input_category == meta_category and
        input_device and input_device == meta_device):
        match_idx = i
        break
    # 如果没有 metadata 标识，回退到 text_hash 匹配
    elif not input_category and not input_device:
        if meta.get('text_hash') == text_hash:
            match_idx = i
            break
```

### 影响函数
- `add_memory`

## Bug 6: 测试集合名被重复使用

### 现象
```
❌ 边界 - 切换不存在集合: 应返回错误: False
```

### 原因
测试中使用的集合名 `nonexistent_collection_xyz` 在之前的测试运行中被创建，导致边界测试失效。

### 修复
1. 使用唯一性强的集合名（如 `__definitely_not_exist_12345__`）
2. 测试前清理所有测试集合
3. `switch_collection` 已有存在性检查（调用 `list_collections()` 验证）

### 影响函数
- `switch_collection`（已有检查，测试用例需改进）
